## The one systemic spacing observation (Audit 6)

`html`/`body` `font-size` is **14px**, not the browser default 16px. Every Tailwind
rem-based spacing utility therefore resolves to a multiple of 14 — proved live with a
`p-5` probe returning **17.5px**. So two spacing systems coexist:

- **Tailwind rem utilities** → 7px, 8.75px, 10.5px, 14px, 17.5px, 21px (`/`, `/pipeline`)
- **px design tokens** (`--space-xs..xl` = 4/8/12/16/24px) → 12px, 16px, 20px, 24px (everywhere else)

This is the root cause of every fractional padding and card-gap value in the app, and it
explains the Dashboard-vs-Pipeline-vs-Reports card spacing spread in one sentence.
Reconciling it means rewriting the spacing of two working pages, which the QA charter
forbids. **Recorded as the best-defined refactor candidate in the backlog** alongside the
form-label drift.

## Tester-error trap that cost this run turns

**A naive comment/string stripper treats the apostrophe in JSX text (`Don't`) as a string
delimiter and eats the rest of the file.** Every setter call in the swallowed region then
reads as "never called". The first pass reported **16** frozen-state hits; **9 were this
artifact** (all 5 StormMap map-control setters, all 4 Dashboard filter setters) and died
to a one-line `grep`.

Two fixes, both now in the kept harnesses:
1. A quote only opens a string in **expression position** (previous non-space char is not
   `[A-Za-z0-9_$)\]]`), and a `'`/`"` string **never spans a newline**.
2. Blank stripped text with **spaces, preserving newlines**, so offsets still map to the
   raw file and reported line numbers are correct. Assert `code.length === raw.length`.

Corollary worth keeping: eating code can only *invent* "never called" hits, never hide
one — so a set difference of this shape is a **superset of the truth**, and every hit must
be confirmed by `grep` against raw source before it is filed.
