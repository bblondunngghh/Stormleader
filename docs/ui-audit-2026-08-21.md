PART 2 — NEW BEHAVIOURAL CHECKS (where the run was spent)
=======================================================

Harness: server/.qa-r84-s3-undefref.mjs (2 set differences, both self-tested against the
pre-fix file so a "0" is evidence rather than a broken check).

--- CHECK A: JSX component tags with no import/declaration ---
An uppercase JSX tag whose only whole-word occurrences in the file are tag positions is
neither imported nor declared -> ReferenceError at RENDER time. The existing Run 83 harness
(.qa-r83-s2-scopediff.mjs) explicitly skips this class: `if (/^[A-Z]/.test(id)) continue`.

  RESULT: 1 hit, REAL, FIXED.  EstimatesView.jsx:2929 <IconCheck> -- used on the
  "Accept & Sign" button, absent from the ./Icons import list (Icons.jsx:181 exports it).

--- CHECK B: cross-branch dead state ---
A component with an early `if (cond) { return <jsx> }` plus a main return has two mutually
exclusive render branches. A useState pair whose SETTER fires inside the early branch while
the branch NEVER reads that state means the control calling the setter is 100% dead.

  RESULT: 1 hit, REAL, FIXED.  EstimatesView.jsx -- "Sign Now" (:1656, review branch) called
  setShowSignModal(true), but {showSignModal && <InPersonSignModal/>} was rendered only in
  the editor branch (:2786), unreachable while reviewMode is true.

--- Triage of CHECK B's other hits (all FALSE POSITIVES, all confirmed by reading source) ---
Every one collapses to a single shape: THE SETTER (or a sibling in the same handler) FLIPS
THE BRANCH CONDITION, so the next render lands in the branch that holds the reader.
  * EstimatesView "Send for Signing" (:1676) -- `setReviewMode(false); setShowSendModal(true)`.
    This is the CORRECT idiom, sitting one button away from the broken one. Its presence is
    what proves Sign Now's omission was an oversight, not a design choice.
  * ContractsView showBuilder / SettingsView showForm -- escape hatches
    (`onCancel={() => setShowBuilder(false)}`); the branch tests the state its setter clears.
  * Dashboard editing / editValue -- a 3-branch state machine; the setter moves it to the
    branch that reads the value.
  * Pipeline selectedStage -- read into the derived const `effectiveStage` (:614) OUTSIDE the
    branch and consumed INSIDE it (:748). Also mobile-only (`if (isMobile)`), out of charter.
Encoded that suppression into the harness: pre-fix file now yields EXACTLY the 1 real defect
with ZERO false positives.
