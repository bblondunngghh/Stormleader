## Set differences run this run

Three source-level set differences (the technique that has produced the finding in 6 of the
last 7 runs). All three are now **CLOSED** — re-run only if the codebase gains a new family.

1. **JSX props passed vs props the component destructures** (194 components, 83 with usages).
   4 hits, all killed: `Panel` and `ToggleSwitch` are same-name collisions across files (each
   file's own declaration takes the props); `SmsComposer` (`LeadDetail.jsx:2157`) really is
   passed 5 props it does not read, but it only ever needed `name` — dead args, no defect.
2. **Form-bound `useState` vars never read anywhere but their own `value={}` binding**
   (93 bound state vars across 76 files). 1 hit, killed: `AddressSearch.jsx`'s `query` is
   display-only; the search runs off `e.target.value`.
3. **Client PATCH/PUT payload keys vs the server's `allowedFields` whitelist** — the check
   that produced `6c21288` tonight, extended to every remaining entity. Subcontractors,
   expenses, tasks, invoices, work orders, leads and tenant-settings **all match**. The
   contracts mismatch was the one real hit and is fixed in `8a5fd0d` (below).

## Fix committed this run

**`8a5fd0d` — contract builder saved nothing and always reloaded blank.** Four defects on one
path, left uncommitted in the working tree by the s2 frontend-test stage when it hit
`max_turns`; verified against the source and committed here rather than lost.

- `POST /api/crm/contracts` read camelCase (`leadId`/`templateType`) while its only caller
  sends snake_case → every "Save Draft" 400'd with `lead_id is required` while a valid
  `lead_id` sat in the body. Both spellings now accepted.
- The payload sent `customer_name/email/phone/address` at the top level; `updateContract`'s
  whitelist is `lead_id/estimate_id/template_type/content` (`contractService.js:108`) and the
  table has no `customer_*` columns, so all four were dropped. They now ride inside `content`,
  where `createContract` already writes the customer data it derives from an estimate.
- Edit-hydration read those same absent columns → reopening a contract always showed empty
  customer fields.
- The template picker read `contract.template_id`; a contract records `template_type`, so the
  picker showed whichever template was first and every save filed the contract as `standard`.

## Verdict

Audits 1–7 pass. Every geometric or colour outlier measured this run resolves to an
