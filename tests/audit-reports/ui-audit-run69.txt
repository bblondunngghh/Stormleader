AUDIT: KEYBOARD FOCUS RINGS (new axis this run) .......... 1 DEFECT — FIXED
================================================================================
Motivation: 58c061f (previous stage) fixed .nav-link and the calendar toolbar
by beating an `outline: none !important` chrome reset — the classic shape of a
partial fix that leaves siblings broken. So every focusable control type was
walked with REAL keyboard Tab (programmatic .focus() does not match
:focus-visible and would have produced a false pass).

Result — every control gets 1px solid oklch(0.55 0.12 250 / 0.3) EXCEPT:

  input[type=checkbox]  outline NONE + box-shadow NONE  <- DEFECT, FIXED
  input[type=range]     outline NONE + box-shadow NONE  <- DEFECT, FIXED
  .address-search__input (StormMap) outline NONE + no glow <- map code, documented only

ROOT CAUSE  index.css:4392
    .form-input:focus-visible, input:focus-visible,
    textarea:focus-visible, select:focus-visible { outline: none; }
  Correct for text entry, which substitutes a border + glow
  (.form-input:focus at :2289, .topbar__search input:focus at :491).
  Checkbox/radio/range are appearance:none custom chrome (index.css:3419) with
  NO substitute, so the blanket rule left them with zero focus indication.

PROOF (real Tab, /leads "Select all leads on this page", 23 hops)
                    before fix              after fix
    outline         none                    1px solid oklch(0.55 0.12 250/0.3)
    outline-offset  -                       2px
    box-shadow      none                    none
    border          2px --glass-border      2px --glass-border  (unchanged)
    vs unfocused    IDENTICAL               unfocused still NONE
    border-radius   50%                     50%  (circle preserved)
  Screenshots: C:/tmp/r69-checkbox-focused.png (before)
               C:/tmp/r69-checkbox-focused-AFTER.png (after)

REACH  26 checkboxes in the /leads tab order (select-all + 25 rows) and the
       storm-map layer toggles.

FIX  11cbe8d — additive rule, [type] attribute raises specificity above
     `input:focus-visible` so text inputs are untouched and order is irrelevant.
     Build exit 0 (8.03s).
