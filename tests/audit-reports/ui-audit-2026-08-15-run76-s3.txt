DEFECT 1 — TWO CSS VARIABLES THAT DO NOT EXIST  (fix 383ba4f)
--------------------------------------------------------------------------------
client/src/components/AlertSettings.jsx referenced:
    var(--border-subtle)   x4
    var(--bg-elevated)     x4
Neither is defined anywhere in the repository. :root defines --glass-border and
--glass-bg; these two names were invented at the call site. Repo-wide grep after
the fix: 0 remaining references.

WHY IT MATTERS — the failure mode is worse than "wrong colour":
An unresolvable var() makes the WHOLE declaration invalid at computed-value
time. Because the code wrote the BORDER SHORTHAND:

    border: '1px solid var(--border-subtle)'

...all three longhands reset to their initial values, so border-style became
`none` and border-width became 0. The control lost its border ENTIRELY rather
than merely mis-colouring it. Measured on /alerts before the fix:

    stepper container  border: 0px none oklch(0.95 0.005 260)   bg: rgba(0,0,0,0)
    decrease button    border: 0px none oklch(0.65 0.2 25)      bg: rgba(0,0,0,0)
    stepper input      border: 0px none oklch(0.95 0.005 260)   bg: rgba(0,0,0,0)
    Send Test Alert    border: 0px none oklch(0.95 0.005 260)
    REFERENCE .glass   border: 1px solid oklch(0.5 0.02 260/0.15)

Visually (screenshot .playwright-mcp/r76s3-alerts-before.png): the "Min Hail
Size (inches)" and "Min Wind Speed (mph)" steppers rendered as bare text with
two loose - / + glyphs floating beside a number. No box, no field, no affordance
that they were editable — sitting directly below an "Add email address"
.form-input showing full glass chrome, in the same panel.

FIX: repointed all 8 references at tokens that exist —
  --border-subtle  ->  var(--glass-border)
  --bg-elevated    ->  var(--glass-bg)            (email + alert-history rows)
  --bg-elevated    ->  oklch(0.22 0.02 260 / 0.45) for the stepper itself,
                       which is .form-input's own background, because the
                       stepper is a FORM CONTROL and shares a panel with one.
Verified after (r76s3-alerts-after.png): stepper border+background now
byte-identical to .form-input, Send Test Alert byte-identical to .glass.
No border doubling despite container+children both carrying borders.

DEFECT 2 — A CLASS NAME THAT MATCHES NOTHING  (fix 5ae8bfb)
--------------------------------------------------------------------------------
ImportLeadsModal.jsx:325 renders the "Importing leads..." loading indicator as
    <div className="skeleton-shimmer" style={{width:48,height:48,...}} />
There is no .skeleton-shimmer selector. The app's shimmer class is `.skeleton`
(index.css:4309). "skeleton-shimmer" exists ONLY as a @keyframes name inside
Dashboard.jsx's inline <style> — and that block is not even mounted here,
because the modal is opened from LeadList, not Dashboard.

Proven in the live document WITHOUT triggering a real import (which would have
written rows and geocoded): injected both classes and read computed style.
    .skeleton-shimmer -> background-image: none        animation-name: none
    .skeleton         -> linear-gradient(90deg,...)    animation-name: shimmer 1.5s
So the user saw a 48px empty gap where a spinner should be, for the whole
duration of a CSV import. Changed to `.skeleton`.

DEFECT 3 — AN UNUSED FOREIGN ICON FONT  (fix 5ae8bfb)
--------------------------------------------------------------------------------
index.html loaded, on every single page view:
    fonts.googleapis.com/css2?family=Material+Symbols+Outlined:...
Evidence it was pure dead weight:
  - zero references to "material-symbols" in any .jsx/.js/.css
  - zero elements on any route resolve to that font-family (measured)
  - zero elements carry fa-*/material-*/mdi/bi-/glyphicon classes (measured)
A render-blocking request for an icon library the project's rules forbid.
Removed. Plus Jakarta Sans / Space Grotesk untouched and still loading.

REUSABLE LESSON FOR THE NEXT STAGE
================================================================================
Run 75-s3 found its bug by diffing classNames USED in JSX against selectors
DEFINED in CSS. This run got 3 more by asking the same question about THREE MORE
KINDS OF NAME, all in one script:

    var(--x) referenced        vs   --x: defined          -> 2 hits (DEFECT 1)
    animation: <name> used     vs   @keyframes <name>     -> triaged, see below
    className used in JSX      vs   .selector in CSS      -> 1 hit  (DEFECT 2)
    icon import specifiers     vs   the allowed package   -> 0 real hits

A name that is declared but never defined renders IDENTICALLY to a working one
whenever something else supplies the styling — and renders as NOTHING when
nothing does. Neither case produces an error, a warning, or a console message.
Screenshots pass. Computed-style sweeps pass. Only the set difference finds it.

*** AND THE MATCHING DISCIPLINE: EVERY CANDIDATE MUST BE MEASURED BEFORE FILING.
The static script produced 3 undefined vars, 5 undefined keyframes and 9
undefined classes = 17 candidates. Only 3 were real. The killers were:
  - `animation: spin 0.6s` (index.css:3014, the AddressSearch spinner) has NO
    @keyframes spin in index.css — but a runtime CSSOM dump shows `spin` IS
    defined by third-party CSS. The spinner spins. NOT A BUG. A source-only
    grep would have filed this.
  - `page-fade-in` (.tab-content) and `--tc` (.lg-storm-row__badge) ARE
    genuinely undefined — but both selectors have ZERO usages in any .jsx.
    Dead CSS, nothing renders. Not user-visible, out of charter.
  - `skeleton-shimmer`, `mobileEstPulse`, `mobilePulse` keyframes are defined
    inside component-local <style> blocks, so a search of index.css alone
    calls them undefined. Only mobileEstPulse/mobilePulse are co-located with
    their user; skeleton-shimmer is NOT, which is exactly DEFECT 2.
  - `group`, `-mx-1` are Tailwind; `o`, `activeIdx`, `timeRange` are template-
    literal parse artifacts; `lead-list-toolbar`, `mini-storm-map`,
    `public-estimate-company` are unstyled BEM/hook wrappers (benign).
So: STATIC SET-DIFFERENCE TO GENERATE CANDIDATES, RUNTIME MEASUREMENT TO
CONFIRM. Neither half alone is sound — the static half over-reports by ~5x,
and the runtime half cannot see the defect at all.

The harness is checked in at server/.qa-r76s3-setdiff.mjs and writes
C:/tmp/r76s3-setdiff.json. Re-run it every UI audit; extend it with a new kind
of NAME each run rather than re-inspecting the same rendered output.

WHAT THIS SWEEP IS STRUCTURALLY UNABLE TO FIND
  - Names built at runtime by string concatenation (`btn-${variant}`), which
    neither half of the check can resolve.
  - Anything on the 4 routes not swept: /storm-map and /canvassing (Google/
    Mapbox, off-limits FEMA/map code), /leads/:id detail, and the 6 public
    token routes (/estimate/:token etc, which need a live token).
  - Styling that is wrong but VALID — every check here asks "does this name
    resolve", never "is the resolved value the right one".
