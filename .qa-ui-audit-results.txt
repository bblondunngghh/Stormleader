AUDIT 7: MODAL CONSISTENCY — PASS WITH 1 NOTE
============================================================
Probed 10 routes by clicking each page's primary create button.

Modals that opened with .modal-backdrop:
  Route          | z-index | bg-opacity | child border-radius | width
  ---------------|---------|------------|---------------------|------
  /pipeline      |   300   |    0.5     | 20px / 18px         | 440
  /leads         |  9999   |    0.6     | 14px                | 720
  /expenses      |  9999   |    0.6     | 20px                | 480
  /work-orders   |  1000   |    0.6     | 20px                | 520

Modals that did NOT open as .modal-backdrop overlays:
  /tasks         — TaskQuickAdd inline form (intentional, not a modal)
  /estimates     — navigates to /estimates/new (builder route)
  /invoices      — navigates to /invoices/new (builder route)
  /contracts     — navigates to /contracts/new (builder route)
  /subcontractors — uses .slide-over.glass slide-in panel
                    (documented in Run 38)

Note (cosmetic): the 4 .modal-backdrop modals that DID open all
share the same class + same animation, but have inline style
drift:
  - z-index 300 / 1000 / 9999 (3 distinct values)
  - bg-opacity 0.5 vs 0.6 (10% difference)
  - border-radius "20px / 18px" vs "20px" vs "14px"
    (Import Leads modal has the smallest corners — visibly
     different from the Add Lead modal)

Root cause: each modal sets backdrop styling inline in the
component instead of relying on the .modal-backdrop CSS rule,
which only declares animation. ImportLeadsModal also references
`var(--radius-2xl)` and `var(--space-2xl)` — only `--space-2xl`
(32px) is defined, `--radius-2xl` is undefined and falls back
to a default border-radius from elsewhere.

NOT a functional defect — every modal opens, animates, closes,
and stacks above the page correctly. Highest visible z-index
in the app is 9999 (CustomSelect portaled dropdowns), and all
modals are below that, so portal dropdowns render correctly
above any modal.

Treating as drift / not fixed under the "don't refactor working
features" rule. Recorded for future cleanup if a modal
component is touched anyway.

Verdict: pass (no functional defect); flagged for awareness.
