Bugs fixed this run
===================
1. ImportLeadsModal.jsx:166 — modal-backdrop div was missing the standard inline
   styling (position/inset/zIndex/background/blur). The .modal-backdrop CSS class
   only carries the fade-in animation, not the visual overlay. Result: when the
   user clicked "Import" on /leads, the modal panel appeared but with no darkened
   backdrop behind it, leaving the underlying page fully visible and click-through.

2. DripSequences.jsx:572 — same bug pattern on the delete-confirmation modal.

Both fixed with the standard inline pattern used by ExpensesView, CalendarView,
MaterialsView, etc.:
   position: fixed, inset: 0, zIndex: 9999,
   display: flex, alignItems: center, justifyContent: center,
   background: oklch(0 0 0 / 0.6), backdropFilter: blur(8px).
